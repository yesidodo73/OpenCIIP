# 아키텍처

## 프로젝트 방향

OpenCIIP는 주요정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드를 기반으로 시스템을 점검하고, 사용자가 승인한 경우 자동 조치를 수행하는 도구입니다.

최초 구현 및 검증 대상은 Rocky Linux 9.8입니다. Rocky Linux 9.8에서 실제로 검증된 기능만 초기 지원 범위로 표시하며, 현재 검증 완료로 선언한 OS는 없습니다.

현재 Rocky Linux 9.8 플랫폼 바인딩, U-01~U-67의 실효 규칙 바인딩, 세 개의 내장 조치 정의는 모두 `pending`입니다. 읽기 전용 점검은 최종 확정 상태를 제한하고, 자동 조치는 계획 단계에서 verified platform·rule·recipe gate를 통과하지 못하면 중단합니다. 내장 조치는 기존 일반 파일에서 허용되지 않은 소유자 UID와 mode의 금지 비트만 최소 변경하는 `file_metadata`로 제한되며, 허용된 소유자·더 엄격한 mode·GID·내용·inode는 보존합니다. 파일 내용과 서비스 변경은 현재 지원하지 않습니다.

| 범위 | 현재 상태 | 검증 현황 |
|---|---|---|
| Rocky Linux 9.8 amd64 | `targeted` / `pending` | 일반 서버 한 대에서 전체 테스트·race·vet·빌드, 67개 읽기 전용 점검(`ERROR` 0개)과 임시 일반 파일 metadata smoke 완료 |
| Rocky Linux 9.8 arm64 | `targeted` / `pending` | 미검증 |
| 그 밖의 OS·버전 | `unsupported` | 별도 구현·VM 증적 전에는 지원하지 않음 |

Linux 공통 동작과 RHEL 계열 공통 동작은 재사용 가능한 계층으로 분리하되, 공통 구현이 존재한다는 이유만으로 검증하지 않은 배포판이나 버전을 지원 대상으로 표시하지 않습니다. 장기적으로 Unix, Windows, 웹 서비스, 보안 장비, 네트워크 장비, 제어시스템, PC, DBMS, 이동통신, 웹 애플리케이션, 가상화 장비, 클라우드 영역까지 확장할 수 있어야 합니다.

## 기술 기준

- 언어: Go 1.26
- 배포: 단일 바이너리
- 최초 검증 대상 OS: Rocky Linux 9.8
- 우선 아키텍처: Linux amd64, arm64
- CLI: Cobra
- TUI: Bubble Tea v2
- 규칙 형식: YAML
- 기본 네트워크 동작: 외부 요청 없음
- 실행 권한: 읽기 가능한 범위의 점검은 일반 사용자도 가능하며, 전체 수집과 조치 계획·실행은 root 권한 필요
- 기본 모드: 읽기 전용 점검
- 우선 인터페이스: TUI

## Go와 셸의 역할

기본 로직은 Go로 구현합니다.

Go가 담당하는 영역:

- CLI와 TUI
- 규칙 로딩
- 명령 실행
- 결과 판정
- 자동 조치 승인 흐름
- 백업과 롤백
- 증적 저장
- 보고서 생성
- timeout과 오류 처리

셸은 Go보다 명확하고 안전한 경우에만 제한적으로 사용합니다. 핵심 로직을 다수의 외부 `.sh` 파일로 분산하지 않습니다.

## 플랫폼 추상화

내부 구현은 다음 정보를 식별할 수 있어야 합니다.

- 배포판 계열
- 배포판 이름
- 버전
- init 시스템
- 패키지 관리자
- PAM 구조
- SSH 설정 경로
- 서비스 관리자
- 방화벽 도구

초기에는 systemd를 우선 지원하되 OpenRC, SysVinit, BusyBox init, init이 없는 제한 환경으로 확장할 수 있어야 합니다.

플랫폼 구현은 다음 계층을 기본으로 합니다.

```text
가이드 규칙
└── 점검 프로필
    └── Linux 공통 구현
        └── RHEL 9 계열 구현
            └── Rocky Linux 9.8 예외 및 검증 정보
```

공통 계층에는 점검의 의미, 수집 인터페이스, 공통 자료 구조를 둡니다. 배포판이나 버전에 따라 달라질 수 있는 명령, 설정 경로, 서비스 이름, 출력 파싱은 플랫폼 구현에 둡니다.

상위 계층의 구현을 하위 플랫폼에 적용할 때는 해당 플랫폼에서 검증되었는지 별도로 확인합니다. 검증되지 않은 구성에 공통 구현을 추측 적용하지 않으며, 자동 판정 근거가 충분하지 않으면 `UNKNOWN`으로 처리합니다.

플랫폼 탐지는 배포판·버전·아키텍처 등 호스트 사실 수집과 지원 상태 결정을 분리합니다. 탐지기에 Rocky Linux 9.8 같은 특정 대상의 지원 상태를 하드코딩하지 않고, 정확한 `id`와 `version` 선택자를 가진 바인딩 계층의 `platform_verification`을 규칙 번들이 결정적으로 해석해 `PlatformInfo.Support`와 검증 경고를 설정합니다. Linux 공통과 `version_major` 계층에는 플랫폼 검증 선언을 허용하지 않습니다.

일치하는 검증 선언은 규칙 바인딩과 같은 `priority`, 계층 `id` 순서로 병합합니다. 최종 상태가 `pending`이면 구현 대상이지만 미검증인 `targeted`, `verified`이면 검증된 `verified`, `rejected`이거나 정확한 선언이 없으면 `unsupported`입니다. 플랫폼 지원과 규칙·조치 정의 검증은 서로 독립된 gate이며 어느 하나도 다른 검증을 암묵적으로 승격하지 않습니다. 아키텍처를 생략한 선언은 일치하는 모든 아키텍처를 포괄하므로 그 전체 범위를 검증하기 전에는 완료 상태로 전환하지 않습니다.

## 다국어

현재 사용자 인터페이스와 문서는 공식적인 한국어만 제공합니다. 별도 locale 파일이나 언어 선택 인터페이스는 아직 구현하지 않았습니다. 다국어 지원을 추가할 때는 사용자 문자열을 locale 자원으로 분리하고 공개 CLI·보고서 호환성을 함께 설계합니다.
